# 🚨 คู่มือปฏิบัติการปลดล็อกฉุกเฉินและแนวทางทดสอบคลินิกนำร่อง (Break-Glass Runbook & Pilot Guide)
**TSPI Botany-Engine: Emergency Break-Glass & Clinical Trial Operational Protocols**  
**ฉบับบุคลากรทางการแพทย์และทีมควบคุมความปลอดภัย (v2.1 Institutional Edition)**  
**วันที่ประกาศใช้:** 26 ตุลาคม 2026

---

## 1. วัตถุประสงค์ของ Break-Glass Protocol

ในเวชปฏิบัติจริง อาจเกิดเหตุฉุกเฉินวิกฤต เช่น:
1. คนไข้มีภาวะฉุกเฉิน หมดสติ หรือความดันวิกฤตที่ต้องดูประวัติการแพ้ยาและผลแล็บทันที
2. แพทย์เจ้าของไข้ติดเคสผ่าตัด หรือไม่สามารถติดต่อได้
3. เกิดปัญหาทางเทคนิคกับรหัสผ่านเปิดกล่องส่วนตัว (Personal Box Password) ในภาวะฉุกเฉิน

**Break-Glass Protocol** คือกลไกความปลอดภัยขั้นสูงที่อนุญาตให้แพทย์หรือบุคลากรทางการแพทย์ที่มีสิทธิ์เข้าถึงข้อมูลในกล่องเวชระเบียนได้ทันที โดยไม่ต้องใช้รหัสผ่านส่วนตัวของแพทย์เจ้าของไข้ แต่แลกด้วย **มาตรการตรวจสอบความโปร่งใสสูงสุด (Total Traceability)**

## 2. ขั้นตอนปฏิบัติการปลดล็อกฉุกเฉิน (Step-by-Step Procedure)

```
[ขั้นตอนการใช้งาน Break-Glass]
1. เข้าสู่หน้ากล่องเวชระเบียนที่ต้องการเปิดตรวจ (Box Detail)
   │
2. ที่หน้าจอล็อก (Vault Lock Screen) ด้านล่าง ให้กดปุ่ม:
   [🚨 Break-Glass Protocol: ปลดล็อกทันที]
   │
3. กรอก "เหตุผลความจำเป็นทางคลินิกอย่างละเอียด" (Clinical Justification)
   - บังคับความยาวอย่างน้อย 10 ตัวอักษร
   - ตัวอย่าง: "คนไข้หมดสติเฉียบพลัน หายใจหอบเหนื่อย แพทย์เจ้าของไข้ติดเคสผ่าตัด ต้องตรวจประวัติยาด่วน"
   │
4. กดยืนยันปลดล็อก
   │
5. ระบบดำเนินการ 4 ประการพร้อมกันทันที:
   ├── ถอดรหัสและเปิดแสดงข้อมูล SOAP, แล็บ, มัลติมีเดีย และ 39 แกน
   ├── บันทึก Immutable Audit Trail ระดับ CRITICAL (เก็บชื่อผู้เปิด, IP, เวลา, เหตุผล)
   ├── ทำเครื่องหมายกล่องเป็น `is_break_glass = True` แสดงแถบเตือนสีแดงถาวร
   └── ยิง Notification ฉุกเฉินไปยัง Medical Director และ DPO
```

## 3. ระเบียบปฏิบัติหลังการเปิดกล่องฉุกเฉิน (Post-Incident Review)

1. **การทบทวนเคสภายใน 24 ชั่วโมง:**  
   เจ้าหน้าที่คุ้มครองข้อมูลส่วนบุคคล (DPO) และผู้อำนวยการฝ่ายการแพทย์ จะได้รับบันทึก AuditLog อัตโนมัติ และจะทำการสอบทาน (Review) ว่าเหตุผลทางคลินิกที่ระบุมีความสมเหตุสมผลหรือไม่
2. **การลงนามคำสั่งการรักษา:**  
   แพทย์ผู้ทำการ Break-Glass ต้องลงนามบันทึกคำตัดสินการรักษา (Clinical Verdict: APPROVE/MODIFY/REJECT/REFER) พร้อมเหตุผลประกอบเพื่อปิดรอบการตรวจ
3. **การเก็บรักษาหลักฐาน:**  
   ประวัติการเปิดแบบ Break-Glass จะถูกล็อกแบบไม่สามารถลบหรือแก้ไขได้ (Immutable WORM Compliance) ตามมาตรฐานเวชระเบียนสากล

## 4. แผนงานการทดสอบคลินิกนำร่อง (Pilot Checklist สำหรับแพทย์ 2-3 ท่าน)

### สัปดาห์ที่ 1: Onboarding & Box Password Setup
- [ ] แพทย์ผู้ร่วมทดสอบ 2-3 ท่าน เข้าสู่ระบบผ่าน `http://localhost:8000/doctor/`
- [ ] ตั้งค่ารหัสผ่านเปิดกล่องส่วนตัว (Personal Box Password) ขั้นต่ำ 6 หลัก ที่หน้าโปรไฟล์แพทย์
- [ ] ทดลองเปิดตรวจกล่องจำลอง 5 เคส (เคสปกติ, เคสผลแล็บผิดปกติ, เคสประวัติซับซ้อน)

### สัปดาห์ที่ 2: Clinical Workflow Evaluation
- [ ] ตรวจสอบความถูกต้องของร่าง SOAP Note ที่ Groq Engine สังเคราะห์
- [ ] ตรวจสอบความแม่นยำของ 39 แกนชีวภาพและการเชื่อมโยงตำรา (Compendium Citations) จาก DeepSeek-R1
- [ ] ทดลองกดปุ่มตัดสินใจทางการแพทย์:
  - อนุมัติแผนการรักษา (Approve)
  - ปรับแก้คำสั่งยา/การตรวจ (Modify)
  - สั่งตรวจซ้ำ (Reject)
  - ส่งต่อแพทย์เฉพาะทาง (Refer)

### สัปดาห์ที่ 3: Simulation & Drills
- [ ] ซ้อมแผนจำลองกรณีฉุกเฉิน Break-Glass 1 ครั้ง
- [ ] ทดสอบความเสถียรในการประมวลผลและการเปิดใช้งานพร้อมกัน
- [ ] กรอกแบบประเมินความพึงพอใจและข้อเสนอแนะทางคลินิก (Clinical UX & Safety Feedback)
