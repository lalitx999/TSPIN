## 1. คำนิยามของ 5% ที่เหลืออยู่ (The Remaining 5% to Pilot Launch)

เพื่อให้คณะกรรมการและบอร์ดบริหารเข้าใจตรงกันอย่างโปร่งใส สถานะระบบในปัจจุบันคือ:
- **Code + Test Architecture = 100% สมบูรณ์** (145/145 Automated Tests ผ่านครบ)
- **Pilot Readiness = 95%** โดย **5% ที่เหลือเป็นขั้นตอนปฏิบัติการภาคสนามของมนุษย์ (Operational Fieldwork)** ซึ่งประกอบด้วย:

## 2. เกณฑ์ชี้วัดความสำเร็จของคลินิกนำร่องและการตัดสินใจ (Pilot Success & Decision Matrix)

### 2.1 เกณฑ์การสุ่มตัวอย่างและโควตาขั้นต่ำ (Sampling & Doctor Quotas)
- **จำนวนเคสรวมทั้งสิ้น:** 15 เคสขึ้นไป (เคสจำลองและเคสนำร่อง)
- **โควตาแพทย์ผู้ร่วมทดสอบ:** แพทย์อย่างน้อย 3 ท่าน **ต้องตรวจอย่างน้อยท่านละ 5 กล่องเวชระเบียน ($\ge 5$ เคส/ท่าน)**
- **เหตุผลทางสถิติ:** ป้องกันความลำเอียง (Bias) ที่อาจเกิดจากแพทย์คนใดคนหนึ่งตรวจเคสทั้งหมด เพื่อให้ได้ข้อเสนอแนะที่สะท้อนการทำงานจริงของบุคลากรที่หลากหลาย

### 2.2 เกณฑ์ชี้วัดหลัก 4 มิติ (Key Performance Metrics)

| ตัวชี้วัด (Key Metric) | เกณฑ์ขั้นต่ำ (Target Threshold) | วิธีการวัดผลอย่างเป็นรูปธรรม (Measurement Method) | ความสำคัญ |
|---|:---:|---|---|
| **1. ความพึงพอใจของแพทย์ (Physician Satisfaction)** | **$\ge 80.0\%$** | คะแนนเฉลี่ยจากแบบประเมินแพทย์ 10 ข้อ (เต็ม 50 คะแนน ต้องได้ $\ge 40$ คะแนน) | การยอมรับในเวชปฏิบัติจริง |
| **2. อัตราการสกัดกั้นข้อมูลหลอน (Guardrail Block Rate)** | **$100.0\%$** | สุ่มตรวจข้อความอ้างอิงตำราและคำวินิจฉัยต้องถูกตรวจสอบผ่าน M8 Guardrail 100% | ความปลอดภัยของผู้ป่วย (Zero Tolerance) |
| **3. อัตราการรั่วไหลของข้อมูล PII (PII Leak Rate)** | **$0.0\%$** | ตรวจสอบ Outbound Request Payload ทุกเคสต้องถูก Sanitizer กวาดล้าง 100% | กฎหมาย PDPA มาตรา 26 (Zero Tolerance) |
| **4. เวลาเฉลี่ยในการตัดสินใจ (Time-to-Decision)** | **$< 5$ นาที/เคส** | คำนวณจาก Database Timestamp Delta ใน AuditLog: `time(BOX_DECISION_RECORDED) - time(BOX_UNLOCKED)` | ประสิทธิภาพและความคล่องตัวในคลินิก |

> **คำจำกัดความ Session การตรวจจริง (Active Session Definition):**  
> หากช่วงเวลาระหว่างปลดล็อกกล่องจนถึงลงนามนานเกิน 30 นาที (เช่น แพทย์เปิดกล่องค้างไว้แล้วติดเคสฉุกเฉินภายนอก) ระบบจะบันทึกสถานะเป็น *Idle Session* และตัดเคสนั้นออกจากการคำนวณค่าเฉลี่ย Time-to-Decision เพื่อไม่ให้ค่าเบี่ยงเบนจากความเป็นจริง

### 2.3 เมทริกซ์การตัดสินใจระดับสถาบัน (Go / Conditional Go / No-Go Matrix)

```
[ตรรกะการตัดสินใจหลังสิ้นสุด Pilot]
┌────────────────────────────────────────────────────────────────────────┐
│ 🟢 GO (ผ่านและอนุมัติใช้งานทั่วไป):                                     │
│    - ผ่านเกณฑ์ครบทั้ง 4 ข้อ 100% (Safety สมบูรณ์ + แพทย์พึงพอใจ ≥ 80%) │
├────────────────────────────────────────────────────────────────────────┤
│ 🟡 CONDITIONAL GO (อนุมัติแบบมีเงื่อนไข พร้อม Sprint แก้ไข 14 วัน):      │
│    - ด้านความปลอดภัย (Safety: Guardrail = 100% และ PII Leak = 0.0%)     │
│      *** ต้องผ่าน 100% เท่านั้น ห้ามผ่อนปรนเด็ดขาด ***                 │
│    - แต่ความพึงพอใจแพทย์อยู่ที่ 75.0% - 79.9% หรือ Time-to-Decision    │
│      เฉลี่ยอยู่ที่ 5.0 - 7.0 นาที                                      │
│    - มาตรการ: อนุญาตให้ปรับปรุง UI/UX 1 รอบ (14 วัน) แล้วประเมินซ้ำ    │
├────────────────────────────────────────────────────────────────────────┤
│ 🔴 NO-GO (ระงับการขยายผลและทบทวนสถาปัตยกรรม):                           │
│    - เกิด PII รั่วไหลแม้แต่เคสเดียว (PII Leak > 0%)                     │
│    - หรือ Guardrail หลุดรอดคำวินิจฉัยต้องห้าม (Block Rate < 100%)       │
│    - หรือไม่ผ่านเกณฑ์ตั้งแต่ 2 ข้อขึ้นไป                                │
└────────────────────────────────────────────────────────────────────────┘
```

## 3. ขั้นตอนการตั้งค่า LINE OA สดเมื่อพร้อมออนไลน์ (Live Webhook Setup Guide)

เมื่อพร้อมเชื่อมต่อกับ LINE Official Account ในระบบจริง ให้ดำเนินการตามขั้นตอนดังนี้:

### ขั้นตอนที่ 1: เปิด HTTPS Tunnel
```bash
# ทางเลือกที่ 1: Cloudflare Tunnel (แนะนำสำหรับ Institutional Production)
cloudflared tunnel --url http://localhost:8000

# ทางเลือกที่ 2: ngrok (สำหรับการทดสอบเบื้องต้น)
ngrok http 8000
```

### ขั้นตอนที่ 2: อัปเดตการตั้งค่าใน `.env`
```ini
LINE_CHANNEL_SECRET=your_actual_channel_secret_here
LINE_CHANNEL_ACCESS_TOKEN=your_actual_access_token_here
```

### ขั้นตอนที่ 3: ตั้งค่า Webhook URL ใน LINE Developers Console
- **Webhook URL:** `https://<your-subdomain>.trycloudflare.com/patient/webhook/`
- **Use Webhook:** เปิด (Enabled)
- **Auto-reply messages:** ปิด (Disabled) เพื่อให้ระบบของ TSPI ตอบสนองเอง
